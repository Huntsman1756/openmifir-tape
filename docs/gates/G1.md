## §1 Purpose and scope of G1

G0 answered: can we capture the frozen corpus from two independent
sources, immutably, with auditable provenance? — **PASS**.

G1 is the **observed universe scale-up** AND the point where the project
acquires its identity: **the Explainable Audit Tape** — an audit-first,
point-in-time, explainable post-trade transparency tape for European
bonds.

The differentiated asset is the combination already proven in G0:
immutable source capture + observation/publication/trading time
separation + regulatory universe resolution + lifecycle reconstruction +
cross-source evidence + fail-closed auditability. G1 surfaces that
combination as a *user-visible primitive*: any derived trade can be traced
back through

```
dataset row → ledger entry/chain → normalized record →
source_object_id + capture_version + raw_sha256 →
eligible manifest observed_at → universe disposition →
FITRS/FIRDS/GLEIF reference evidence
```

and any materialization can be verified offline without opening provider
payloads. This is NOT another ESMA-to-DuckDB loader, NOT a CTP, and NOT a
market-coverage estimator.

```
G0                                   G1
20 frozen sample                     every instrument observed in the
→ 16 INCLUDE                         verified A3 window
→ machinery proven                   → same resolver on all of them
→ 5 intact days                      → INCLUDE/EXCLUDE/QUARANTINE/CONFLICT
→ descriptive metrics on the sample  → explainable, verifiable tape +
                                       divergence ledger + fragmentation
```

Non-goals (explicitly out of scope for G1):

- market coverage or completeness estimation;
- total market universe estimation;
- CTP reconstruction;
- historical backfill before the A3 window;
- UI / API / query service (the CLI contracts in §4 are semantic
  contracts — implementation may arrive across successive issues);
- estimates of unobserved trades.

G1 does not require knowing the "total market universe". The valid
denominator is the OBSERVED instrument set only, and it must always be
labeled as such.

## §3 G1-B — Observed-universe resolution

Every observed instrument identifier resolves through exactly the frozen
`es_legal_issuer_v1` chain (docs/gates/G0.md §3, unchanged):

```
FITRS auth.045: MiFIR ID = BOND AND Bond Type = CRPB (SACL BOND5 only;
    Desc is a cross-check, never sufficient alone)
        ↓
FIRDS RTS 23 field 5: issuer LEI
        ↓
GLEIF: LegalJurisdiction.country = ES
        ↓
INCLUDE / EXCLUDE / QUARANTINE / CONFLICT
```

Hard rules (unchanged from G0):

- no ISIN-prefix heuristics, no issuer completion by hand, no removal of
  awkward cases;
- missing LEI, unresolvable jurisdiction, or identity conflict →
  QUARANTINE or CONFLICT. QUARANTINE and CONFLICT are valid, visible
  results — not failures;
- resolution runs locally against pinned reference snapshots, idempotent
  by document hashes; no provider/reference network calls in CI.

Difference from F-009/G0-B1: the resolver is no longer filtered to the 20
frozen-sample ISINs. G1-B is a BATCH resolver over the whole observed
instrument set, reusing `resolve_disposition()` with identical semantics.
Every disposition carries the reference set_digests (§4.4 canonical
representation) it was resolved against — the capsule must be able to
cite them.

Gate requirement — **100% disposition**: every observed ISIN receives
exactly one explicit branch. No missing row, no silent drop, no
UNCLASSIFIED pseudo-state. A batch run is INVALID if any observed
identifier exits without a disposition.

## §4 G1-C — The Explainable Audit Tape

Materialize the first durable local dataset — the artifact that makes the
project's auditability visible and queryable.

### §4.1 Storage and schema

Storage: `data/g1/tape/` (gitignored; provider data never enters the
repository). Format: **Parquet files + DuckDB as the query engine** —
embedded, no server.

Minimum schema:

```
publications                        trade_chains
------------                        ------------
source                              source
source_object_id                    chain_id
capture_version                     isin
raw_sha256                          transaction_id
known_at                            head_entry_id
last_observed_at                    head_state
observation_count                   event_count
publication_utc                     first_publication_utc
trading_utc                         latest_publication_utc
isin                                first_known_at
transaction_id                      head_known_at
price
quantity
notional
currency
flags
lifecycle_state
ledger_entry_id
supersedes_entry_id
universe_disposition
universe_disposition_reason
issuer_lei
```

### §4.2 Temporal semantics — `known_at` / point-in-time

Three temporal axes MUST be preserved distinctly; never collapse them:

- `trading_utc` — when the event happened economically;
- `publication_utc` — when the source published it;
- `observed_at` — when OpenMiFIR actually knew/captured it.

**Canonical `known_at`.** A unique capture identity
`(source_id, source_object_id, capture_version)` may be attested by
several eligible manifests with different `observed_at`. Freeze:

```
first_observed_at = min(eligible results.observed_at attesting the tuple)
known_at := first_observed_at
```

Repeated observations of identical bytes NEVER advance `known_at`.
`last_observed_at` and `observation_count` are retained in the tape as
diagnostics only.

**`as_of(T)` — reconstruction, not head filtering.** Point-in-time state
MUST be rebuilt through the G0-D machinery:

```
as_of(T) = publications WHERE known_at <= T
           → build_ledger → reconstruct_chains → chain[-1]
           (G0-D ordering, entry_id tie-break included)
```

It is NOT valid to filter the materialized `trade_chains` heads — a chain
whose original publication is at T1, amendment at T2, cancellation at T3
has a different authoritative head at each instant:

```
as_of(T1) → original publication is head
as_of(T2) → amendment is head
as_of(T3) → cancellation is head
```

In the materialized `trade_chains`, `first_known_at` is the earliest
knowledge time of the chain and `head_known_at` the knowledge time of the
current materialized head; neither substitutes for reconstruction.

**No future evidence.** Any `as_of(T)` artifact — including an
EVIDENCE_CAPSULE — cites ONLY evidence with `known_at <= T`. Explaining
the state at T1 must not surface the cancellation known at T3. The G1-D
divergence classes at `known_at = T` use the same reconstruction rule.

This is regulatory point-in-time (deferrals, partial publication,
amendments, cancellations), not generic database versioning.
Implementation naming is deferrable (`omt asof --at <ts>`); the semantics
are not.

### §4.3 EVIDENCE_CAPSULE — the `explain` primitive (mandatory)

For any `publications` row or `trade_chains` head, the tape MUST emit a
deterministic, metadata-only **EVIDENCE_CAPSULE** tracing the full chain
of §1. Minimum fields:

- stable row/chain identifier;
- source, source_object_id, capture_version, raw_sha256;
- `observed_at` (the FIRST eligible manifest observation attesting the
  capture = `known_at`), `publication_utc`, `trading_utc` as distinct
  axes;
- normalized field provenance / source field names for the core economic
  fields;
- lifecycle chain + head + supersession links;
- universe disposition + reason + issuer LEI;
- reference set_digests (FITRS/FIRDS/GLEIF, §4.4) plus the concrete
  reference record(s) used by the disposition;
- generator code commit + dataset semantic digest.

Gate: two independent materializations of the same tape MUST emit
**byte-identical capsules** for the same row/chain. No provider payload
content enters a capsule. An `as_of(T)` capsule cites only evidence with
`known_at <= T` — no future amendment, cancellation, or reference leaks
into a historical explanation (§4.2).

Semantic contract (naming deferrable): `omt explain --chain <id>` /
`omt explain --row <id>`.

### §4.4 TAPE_MANIFEST + offline verify (mandatory)

Every tape build MUST emit one small `TAPE_MANIFEST` metadata artifact.
Reference snapshots are multi-file sets — the manifest records a
canonical representation per family: sorted `{name, sha256, bytes}`
entries plus a `set_digest` computed over the canonical metadata:

```yaml
input:
  a3_bundle_sha256: ...
  eligible_manifest_digest: ...
references:
  fitrs:                    # canonical sorted list; never a single file
    entries: [{name, sha256, bytes}, ...]
    set_digest: ...
  firds:
    entries: [{name, sha256, bytes}, ...]
    set_digest: ...
  gleif:
    entries: [{name, sha256, bytes}, ...]
    set_digest: ...
generator:
  code_commit: ...
  schema_version: ...
outputs:
  publications_rows: ...
  trade_chains_rows: ...
  disposition_counts: {...}
  publications_semantic_digest: ...
  chains_semantic_digest: ...
  dataset_semantic_digest: ...
```

Capsules cite the relevant family `set_digest` plus the concrete
reference record(s) used by the disposition.

`omt verify` separates two layers explicitly:

- **Tape self-verification** — recompute schema, row/table, capsule and
  dataset digests; verify manifest internal consistency and the declared
  pinned input/reference digests. Proves the local tape is the claimed
  materialization *if* the declared inputs are trusted.
- **Full provenance verification** — when `--bundle` and reference
  snapshot paths are supplied: hash the original input bytes and prove
  they match the TAPE_MANIFEST. Hashing bytes is allowed; no provider
  payload content is parsed, emitted, or exposed.

`TAPE_REPRODUCIBLE` (G1 PASS) requires the full materialization replay of
§4.5 — not merely manifest self-consistency.

### §4.5 Reproducibility gate

```
same sealed input bundle
+ same reference snapshots (FITRS/FIRDS/GLEIF, hash-pinned)
+ same code commit
→ semantically-equivalent tape (identical dataset digest)
+ byte-identical evidence capsules
```

Parquet byte-equality is NOT required (writer metadata may vary). The
digest is computed over **canonically ordered rows** — fixed row
ordering, fixed column set, per-table digest plus a dataset digest. Two
independent materializations MUST produce identical digests.

Repository evidence = schema, hashes, counts, TAPE_MANIFEST, capsule
fixtures — never payloads.

## §5 G1-D — Source-divergence ledger + observed fragmentation

Reuse the `metrics/` machinery with scope = all instruments resolved
`INCLUDE` by G1-B. Output: `OBSERVED_FRAGMENTATION_MEASURED`, plus a
per-chain **source-divergence ledger** (metadata only).

Aggregate metrics:

- observed INCLUDE ISINs; ISINs by source; intersection; source-exclusive
  observed sets;
- unique ledger chains by source; head lifecycle-state distribution;
- cross-source economic candidate groups (never merged);
- notional by source and currency; terminal-CANCELLED heads reported
  separately;
- QUARANTINE / CONFLICT counts; reference-data failure reasons;
- explicit census of the eligible input (manifests, unique capture
  versions, excluded pre-window/post-tail manifests).

Source-divergence ledger — per chain/candidate, observed-set semantics
only:

```
membership (exactly one):
  OBSERVED_BOTH | OBSERVED_BME_ONLY | OBSERVED_BLOOMBERG_ONLY
relation flag (independent of membership):
  CROSS_SOURCE_CANDIDATE
divergence classes (where a candidate or per-source chains exist;
reconstructed per §4.2 at the stated known_at):
  PUBLICATION_LAG            — first publication times differ
  STATE_DIVERGENCE           — head states differ at a stated known_at
  AMENDMENT_DIVERGENCE       — amendment observed on one source only
  CANCELLATION_DIVERGENCE    — cancellation observed on one source only
```

Forbidden wording: never `MISSING_FROM_<source>` — an instrument absent
from one source's capture is `NOT_OBSERVED_IN_<source>_CAPTURE`. All
entries describe the observed sets only.

Mandatory limits (verbatim carry-over from G0-E):

- `NO_COVERAGE_CLAIM`;
- `NO_MARKET_SHARE_INFERENCE`;
- `NO_ABSENCE_OF_TRADING_INFERENCE`;
- no low-n generalization.

There is no "observation rate" against an assumed market total. The only
valid denominator is the observed instrument set, always labeled as such.
Absence is always source-scoped — `NOT_OBSERVED_IN_<source>_CAPTURE` —
and never means "did not trade"; it means "not observed in an intact
capture".

## §7 G1 PASS evaluation

G1 is `PASS` only if ALL are demonstrated with committed evidence:

1. the eligible A3 corpus is reproduced exactly (same selection rule,
   same sealed bundle, auditable census);
2. every observed instrument identifier receives exactly one explicit
   regulatory disposition (INCLUDE/EXCLUDE/QUARANTINE/CONFLICT) — 100%
   disposition of the OBSERVED set;
3. no manual overrides, no fuzzy identity, no silent drops;
4. the tape is deterministically reproducible — identical dataset
   semantic digest across independent materializations, and
   byte-identical EVIDENCE_CAPSULEs for identical rows/chains;
5. every tape row traces to source + capture_version + raw_sha256 +
   manifest observed_at;
6. lifecycle chain semantics remain G0-D authoritative (chain[-1] heads,
   append-only, explicit supersession);
7. point-in-time reconstruction is defined and deterministic
   (`known_at := first_observed_at`; `as_of(T)` rebuilds via G0-D from
   publications with `known_at <= T`; as-of artifacts cite no future
   evidence);
8. every build emits a TAPE_MANIFEST (canonical multi-file reference
   sets); `TAPE_REPRODUCIBLE` requires full materialization replay —
   self-verification alone does not satisfy this criterion;
9. the source-divergence ledger and `OBSERVED_FRAGMENTATION_MEASURED`
   report exist, observed-set semantics only;
10. `NO_COVERAGE_CLAIM` holds — enforced by scan at emission, as in
    G0-E1.

Anything else → REVIEW_REQUIRED. The evaluation MUST name the gate
criterion for each component, cite evidence, and label every verdict.
