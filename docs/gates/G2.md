# G2.md — Frozen Gate Specification (v0)

G2 defines a reproducible local temporal/history tape for profile
`es-corporate-bonds`. Authority becomes frozen at `g2-freeze-v0` after
review and merge. That freezes a contract, not an implemented or PASS gate.
G0 (`g0-freeze-v1`) and G1 (`g1-freeze-v0`) remain unchanged authorities
for their artifacts, resolver and lifecycle rules. Contract bootstrap: #45.

## §1 Purpose, boundaries and execution order

Answer: can successive sealed windows and observed reference snapshots
produce reproducible historical views, without future evidence, duplicate
ingest, rewritten observations or hidden acquisition gaps?

Reuse Python, local Parquet and embedded DuckDB. Storage is `data/g2/`,
gitignored; repository outputs are metadata only. Existing operator timers
continue under G0-A. New G2 operational profiles start only after their
tooling is verified and the profile is frozen. No deployment is required
to freeze this document.

G1 PASS (#41), runtime isolation (#16) and verified deployment (#43) are
prerequisites. The G1 corpus/build stays immutable and replayable under
its own selection rule and `BUILD_SNAPSHOT` classification.

Execution: A1 input authority → B1 reference authority → C1 incremental
build → C2 historical audit → A2 prospective operating profile → accrued
operator evidence → A3 operational adjudication → D1 gate evaluation.
Each arrow requires predecessor evidence and successful offline checks.
Agents implement bounded tooling; the existing scheduler accrues days.
Open the A3 outcome-verification issue only after evidence has accrued.

Scope excludes UI/API/server, orchestration, new sources, market totals,
backfill before the G1 origin and inferred historical reference validity.
G3/G4 require their own specifications. G0-L classifications, including
UNRESOLVED cells, remain visible; this gate grants no redistribution rights.

<a id="G2-A"></a>
## §2 G2-A — Window authority and operational continuity

### A1 Sealed input catalog

A window profile binds profile version, source descriptor fingerprints,
sources, UTC start/end, explicit expected trading dates/calendar basis,
G0-A schedule/rescan/retry authority and evidence-tail policy. Freeze it
before a prospective start. A G2 window selects observations by
`results.observed_at` in `[start, end)`, not publication/trading time.
The tail is included in `end`, with its duration declared in the profile.
The observed interval and expected trading dates are distinct metadata.

Import the verified G1 origin by its exact G1-A sealed bundle and inclusive
selection rule; never reinterpret it as a half-open G2 window. Existing
post-tail operator runs do not automatically become verified G2 windows.
Every span between admitted windows is explicitly represented, including
the span from the G1 origin to the first prospective G2 window.

A sealed bundle binds profile hash, sorted manifest names/hashes, journal
metadata authority, acquisition/deployment revisions and UTC seal time.
Metadata names are relative and unique; escapes, conflicting declarations,
missing eligible bytes or hash-divergent raw objects reject admission.
Seal time is packaging provenance, not the observation's knowledge time.
Publish a census of total/eligible/excluded manifests, object attestations,
unique captures, parse failures and admission verdicts. Never silently drop
an identifier or a selected capture that cannot be normalized.

Capture identity remains `(source_id, source_object_id, capture_version)`.
Distinct captures never collapse by economic similarity. An attestation
is keyed by `(source_id, run_id, source_object_id, capture_version)` and
binds the manifest SHA-256 and observation time. Its run identity is
mandatory; conflicting bytes/times for that identity reject admission.
Replaying its manifest under another filename is not a new observation.
One attestation contributes once even across overlapping windows. Keep
every window-membership link and hash-check duplicate physical copies.

Canonical capture `known_at` is the minimum accepted attested observation
time; `last_observed_at` and counts are diagnostic only. Untimed or
ambiguous evidence is invalid, not assigned ingestion or file-mtime dates.
Each new window's start is at/after the preceding prospective window's end;
the G1 origin may overlap the first window only under explicit membership
links. An already accepted attestation is harmless on replay. A newly
introduced older attestation that would backdate an accepted capture or
rewrite a previously sealed interval is rejected: adjudicate it through a
separate versioned correction proposal, never silent incremental import.

### A2 Prospective profile and bounded operator run

After A1/B1/C1/C2 verification, freeze the first prospective profile and
instructions for sealing it. Existing timers obey G0-A; do not add another
scheduler. Record all deployment/source-config changes within the window.
Acquire reference observations locally under B1; provider/reference calls
never run in CI. Stop an unsupported reference acquisition as a recorded
failure rather than guessing an endpoint or successful snapshot.

### A3 Accrued operational outcome

Require G0-A.8's five trading days and operating daily/rolling rescans;
retain its polling/overlap bounds. Use the adjudicator's source-bound
recovery evidence, not an assumed seven-day archive. A missing poll slot
is not recovered merely because a later request succeeded.

The gap ledger covers each source and expected acquisition slot, plus
inter-window spans. Its statuses are `NO_DETECTED_GAP`,
`RECOVERED_SUPPORTED`, `UNRECOVERABLE_SOURCE_BOUND`, `UNEXPLAINED`, or
`NOT_ASSESSED`. Cite expected/actual times, affected interval, source,
run/hash references and recovery proof or failure reason. A source outage
cannot be explained by another source's capture. "No detected gap" applies
only to the stated schedule/profile, never to market completeness.
Assessments carry their actual `assessment_known_at`; recovery appends a
new assessment, never backdated to the affected slot or overwritten.
Historical gap claims select only assessments known by T; unavailable
assessments remain NOT_ASSESSED, even if the gap is adjudicated later.

A window's `COMPLETE_SUPPORTED` requires G0-A.8 and no unexplained or
unrecoverable in-window gaps. Other windows retain explicit
`REVIEW_REQUIRED`/`INCOMPLETE_SOURCE_BOUND` metadata and may be inspected
diagnostically, but cannot satisfy the operational PASS criterion.
Inter-window `NOT_ASSESSED` spans remain visible; they do not imply global
continuous coverage or contaminate an otherwise verified bounded window.

## §3 G2-B — Reference observations and dated classification

### B1 Timed, immutable reference bundles

A reference observation records family (FITRS/FIRDS/GLEIF), local durable
observation UTC, acquisition identity/outcome, source/provenance, scope of
requested identifiers and canonical `{name, sha256, bytes}` entries with
G1-C.4 set digests. Retain concrete record handles and explicit missing,
failed or not-found outcomes. Hashes and timestamps are metadata; reference
payloads stay local. A source's publication/effective date is separate
source evidence and never substitutes for local observation time.

A bundle declares all three families, including explicit unavailable
families/records. Each available file and each acquisition-outcome receipt
must have a timed attestation. `reference_known_at` is their latest
observation time: the entire bundle becomes knowable then. Its identity
binds these attestations, scopes, outcomes and family digests. Repacking or
reobserving identical bytes never retroactively advances availability of
an already accepted bundle. A fresh acquisition episode is a new bundle,
even if its file hashes are unchanged. Canonical sorting removes filename
iteration-order dependence; two different bundles at the same knowledge
time are ambiguous and reject publication until explicitly adjudicated.
New bundles are admitted in increasing knowledge-time order; replay of an
accepted bundle is a no-op. A newly introduced bundle whose observation
falls within an already sealed window rejects incremental admission,
like backdated capture attestations in A1; corrections need a new contract.

Structurally invalid metadata, missing declared-present bytes, unparseable
declared reference files or hash divergence reject the build; do not fall
back silently to an older bundle. Structurally valid recorded acquisition
failures or unavailable records remain valid knowledge of unavailability.
The resolver then returns its frozen fail-closed disposition.

Legacy G1 references have no proven observation timeline. File mtimes,
operator recollection or source dates cannot supply one. They remain
`LEGACY_BUILD_SNAPSHOT` for G1-compatible explanation only, and are never
eligible G2 temporal reference evidence without original timed receipts.
No reference-acquisition cadence or freshness SLA is inferred: always
emit the selected bundle's age and availability/scope limitations.
That age measures local availability, not source-data freshness; preserve
source revision dates when evidenced and mark unknown freshness explicitly.

### B2 Classification as known at T (implemented within B1/C2)

Select the latest accepted bundle with `reference_known_at <= T`.
Do not mix families from independently selected bundles, interpolate, or
carry missing records forward from an older bundle. Label the result
`reference_basis: OBSERVED_REFERENCE_SNAPSHOT`; this means references
observed by T, not legal validity on the trading date or a source revision
history that has not been captured. Cite bundle ID/time, age and concrete
reference handles/outcomes. A newer available bundle with missing scope
must remain missing; it does not authorize an older substitute.

Every instrument observed by T gets exactly one frozen `es_legal_issuer_v1`
disposition. If no timed bundle is yet known, run the same resolver with
unavailable inputs; retain its QUARANTINE reason and add diagnostic
`NO_TIMED_REFERENCE_BASIS` with a null bundle ID. Never borrow future or
legacy G1 snapshots, introduce UNCLASSIFIED, or invent a regulatory reason.

Record decisions append-only per instrument/bundle/resolver version,
including branch, reason, LEI, knowledge time and reference links.
Decision knowledge time is the later of first instrument observation and
selected bundle availability; execution wall-clock time is provenance only.
Reclassification under a newer observed bundle is an explicit new decision;
it does not overwrite the previous decision or normalized publication.
A reference-only update may change the INCLUDE view at T, while earlier
queries and builds retain their previous classifications.

## §4 G2-C — Incremental builds and historical audit

### C1 Publication registry and atomic builds

Store every normalized publication occurrence, whatever its disposition.
Stable publication identity binds the capture tuple plus source record
ordinal; never an economic key, ledger occurrence suffix or database row
number. Retain canonical normalized replay substrate and immutable
normalization version/digest; changed content for an accepted identity
rejects import. G0-C parse failures remain explicit census diagnostics.
Keep old builds addressable; a schema/normalizer change requires a named
migration contract, not a replacement of stored observations.

G0-D remains authoritative. Its IDs/markers can change when an additional
identical observation enters a reconstruction; a supersession chain can
also change when a newly known late publication sorts before the head.
Therefore ledger IDs and `supersedes_entry_id` are scoped to an immutable
build/view, with an exact indexed mapping to stable publication IDs.
Retain every prior view and mapping; never advertise globally stable ledger
IDs or mutate old links. Chain identity and ordering remain G0-D's rules;
unchainable records stay singletons. No fuzzy or cross-source merging.

Incremental import stages and validates raw identities, attestations,
reference bundles, dispositions and candidate outputs before committing
an immutable build. A failed/interrupted import leaves the previous active
build available and records a failure receipt, without partial activation.
Promote only fully verified builds; concurrent writers serialize or fail
explicitly. These are local library/CLI semantics, not a new server.

Reimporting the exact same admitted manifest/reference set changes no
semantic tables, observation counts, build identity or active-build pointer.
Attempt logs may append outside semantic state. A genuinely new attestation
may update diagnostics; a new capture/reference bundle may produce a new
build. Do not conflate observation updates with unintended duplicate ingest.

### C2 Historical view, capsules and offline verification

For the admitted authority of a specified build:

```
as_of(T): publications known_at <= T
          + reference bundle reference_known_at <= T (B2)
          -> dispositions for every observed instrument
          -> G0-D reconstruction over INCLUDE occurrences
          -> heads, divergence and observed-only fragmentation
```

All dispositions and excluded/quarantined/conflicted publication counts
remain inspectable alongside the INCLUDE view. Filter knowledge first;
never filter final heads or final dispositions to infer the past.
G0-D canonical input ordering uses publication identities as a stable
ordering of otherwise identical occurrences; indexed mapping is explicit.
A publication with old trading/publication dates but observed after T is
absent at T. Reference-only changes and late amendments/cancellations
cannot leak into an earlier view. Timestamp offsets normalize to UTC;
naive or invalid cutoffs fail. Results bind build ID, T and reference basis.

Capsules cite only selected publication/reference observation evidence
known by T, plus stable publication IDs, scoped ledger mappings, decisions,
supersession, relevant windows/gaps and code/schema/semantic digests.
Gap outcome evidence must also have `assessment_known_at <= T`.
Container seal/build provenance dates are distinct from observation times.
Economic provider values and normalized substrate never enter capsules or
repository evidence. Preserve all G1-D interpretation labels and scan at
emission; zero INCLUDE results do not imply absence of trading.

Every immutable build emits a metadata manifest binding parent build,
window/profile/bundle hashes, attestation registry, reference timeline,
decision registry, normalization/resolver/schema/code versions, table
counts and canonical semantic digests. Build identity binds admitted
authority, versions and resulting semantic state; execution parent links
are provenance, not part of that identity. Absolute paths, wall-clock build
time and Parquet writer metadata cannot determine semantic identity.

Self-verification and full original-byte provenance are distinct, as in
G1-C.4. G2 reproducibility additionally compares two clean full replays
with the chronological incremental route over the same admitted authority:
identical canonical table/view digests and byte-identical capsules. Capsules
exclude nondeterministic packaging provenance; no semantic field is masked.
Reverse file enumeration must not affect results. The historical view digest
binds T and its selected publication/reference/decision/ledger state, not
future build context. It stays equal if every newly admitted observation is
strictly after T. Capsules identify their build: cross-build provenance may
differ, while this historical semantic section must stay equal.

## §5 G2-D — Evidence and PASS evaluation

Evaluate each criterion explicitly, cite committed metadata and show
PASS or REVIEW_REQUIRED. G2 PASS requires all of:

1. G0/G1 baseline remains verifiable; G1 selection/classification artifacts
   and digests are unchanged.
2. Exact sealed input catalog/census and unique publication/attestation
   identity across the origin plus at least one new admitted window.
3. Timed reference authority, with at least two distinct accepted bundles;
   all observed identifiers have explicit fail-closed dated dispositions.
4. Historical queries and capsules use neither future publication nor future
   reference evidence; untimed legacy references never masquerade as dated.
5. Reference-only update, late publication, amendment/cancellation, identical
   economic occurrences and ambiguous/missing reference counterexamples
   satisfy B/C in deterministic offline fixtures.
6. Second ingest has zero unintended semantic state changes; interruption
   and concurrent-writer counterexamples preserve the last verified build.
7. Immutable prior builds/observations/decisions and indexed scoped G0-D
   mappings remain addressable; no silent rewrite or heuristic merging.
8. Two clean replays equal chronological incremental materialization and
   emit identical historical capsules; original bytes fully authenticate.
9. At least one prospective additional window satisfies A3 with accrued
   operator evidence; the complete gap ledger keeps all inter-window spans
   and incomplete windows visible without continuous-coverage claims.
10. Metadata-only repository evidence, offline CI, mandatory interpretation
    limits, and current G0-L classifications are maintained. Implementation
    matrix and installed CLI checks are green before verification/rollout.

Fixtures prove code semantics; they do not replace live A3 evidence.
Specification freeze, a smoke run or self-verification alone is not G2 PASS.

## §6 G2-F — Freeze and bounded contracts

Changing this specification requires a reviewed PR and a new annotated
`g2-freeze-v*` tag. Record design choices, dependencies and deviations in
the PR; do not edit G0/G1 to make a new implementation pass.

After `g2-freeze-v0` exists, create A1, B1, C1, C2, A2 and D1 contracts
referencing this file's explicit anchors. Put dependency issue IDs in
Allowed scope; issues do not redraft semantics. Initially only A1 is
`ready-for-agent`; dependent contracts remain `planned` until predecessor
verification. A2 includes profile tooling/operating instructions, not a
claim that days have accrued. Create A3 only after the scheduled evidence
exists; D1 cannot verify before A3. Implementation may split a contract
into bounded issue/PR slices without changing this authority.
