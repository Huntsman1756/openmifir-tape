# G3.md — Frozen Gate Specification (v0)

G3 defines the ISO 20022 consolidated-tape compatibility and benchmark
contract for profile `es-corporate-bonds`. Authority becomes frozen at
`g3-freeze-v0` after review and merge. That freezes a contract, not an
implemented or PASS gate. G0 (`g0-freeze-v1`), G1 (`g1-freeze-v0`) and
G2 (`g2-freeze-v0`) remain unchanged authorities for their artifacts,
resolver, lifecycle and temporal rules. This gate does not modify them.

External facts (the ISO 20022 message set, its code sets, its identifiers)
are NOT inlined here; they are referenced by identifier and pinned by digest,
as G0 does with source descriptors.

## §1 Purpose, boundaries and execution order

Answer: can OpenMiFIR project its own verified admitted tape into the ISO 20022
consolidated-tape message model, validate that projection structurally and in
round-trip against a pinned, timed schema snapshot, and declare an offline
benchmark interface for the future official EU bonds tape — without acquiring
new data, without becoming a CTP, and without any coverage, authorisation or
conformance claim?

Reuse Python, local Parquet and embedded DuckDB. Storage is `data/g3/`,
gitignored; repository outputs are metadata only. The projection consumes an
already admitted immutable build; it never acquires a source, and provider or
ISO 20022 artifacts are never fetched in CI.

Prerequisites: G1 PASS (#41) and a verified immutable build from G2-C1, which
supplies the admitted observations the projection reads. G3 re-derives neither
universe disposition nor lifecycle: G0-B, G0-D, G1-B and G2-B/C stay
authoritative and are consumed as-is.

The official bonds CTP is not authorised (see references); this gate therefore
validates structure and declares an interface offline, and never depends on a
live tape. ESMA's ISO 20022 messages for CTP input and output data are relevant
both to the bonds CTP and to the shares/ETF CTP; G3 pins only what this profile
needs and never infers one asset class's semantics from the other.

Execution: A1 schema authority → B1 projection → B2 structural validation →
C1 round-trip and loss accounting → D1 benchmark-readiness contract → L1 legal
classification → E1 gate evaluation. A1 and L1 are independent of the tape and
may start first; B/C/D require a verified G2-C1 build and a verified A1 snapshot.

Scope excludes UI/API/server and any product surface (G4), live CTP acquisition,
new sources, orchestration, market totals and any backfill. The interactive
screen and the discrepancy monitor of the originating proposal are G4, not G3.
G0-L classifications, including UNRESOLVED cells, remain visible; this gate
grants no redistribution rights.

<a id="G3-A"></a>
## §2 G3-A — Pinned ISO 20022 CTP message authority

### A1 Timed, immutable schema snapshot

A schema snapshot records: the ESMA submission identity for CTP data reporting,
the ISO 20022 message-set/message-definition identifiers and versions actually
obtained, the external code sets those definitions reference, the local durable
observation UTC, the acquisition identity and outcome, the source/provenance,
and canonical `{name, sha256, bytes}` entries with G1-C.4 set digests. Hashes and
timestamps are metadata; the acquired schema files stay local.

Input and output are distinct artifacts and MUST be declared separately: a
snapshot that cannot distinguish the contributor→CTP messages from the
CTP→consumer messages is invalid. The snapshot declares which definitions this
profile is required to project and which code sets they reference.

`schema_known_at` is the latest accepted observation time of the snapshot's
attestations; the whole snapshot becomes knowable then. The upstream
registration or publication date of an artifact (for example the registration
of the CTP data-reporting submission) is separate source evidence and never
substitutes for local observation time. A fresh acquisition episode is a new
snapshot even if its file hashes are unchanged. Snapshots are admitted in
increasing knowledge-time order; replay of an accepted snapshot is a no-op.

Structurally invalid metadata, missing declared-present bytes, unparseable
declared schema files, a hybrid snapshot that mixes artifact versions across a
declaration, or hash divergence reject the snapshot. Never fall back silently to
an older snapshot. Two different snapshots at the same knowledge time are
ambiguous and reject publication until explicitly adjudicated.

### A2 Publication status of the pinned artifacts (implemented within A1/B1)

The snapshot records each artifact's publication status exactly as observed.
Definitions that are only available as drafts are pinned as such and every
element projected against them carries `DRAFT_SCHEMA_BASIS`; structural
compatibility is never claimed for a draft element. A later snapshot that pins
final definitions is a new admitted authority and produces a new projection
identity (B1); it never rewrites a prior projection or a prior verdict.

<a id="G3-B"></a>
## §3 G3-B — Structural projection

### B1 Deterministic projection of an admitted build

The projection is a pure function of admitted authority: (G2-C1 admitted build
ID, G3-A schema snapshot ID, declared message direction, target message
definition, code-mapping registry version). It reads the build's publications,
dispositions, lifecycle chains/heads, `known_at` and `reference_basis` as
frozen by G0/G1/G2, and emits ISO 20022 message instances. It recomputes no
universe, lifecycle or temporal semantics and performs no cross-source merging.

Every internal value that must cross into an ISO 20022 code boundary (MiFIR
instrument ID, bond type, lifecycle state, disposition, currency, market
identifier and equivalents) has an explicit entry in a versioned, digest-pinned
code-mapping registry. An unmapped or ambiguous value produces an explicit
`G3_UNMAPPED_<field>` reason and leaves the affected instance
`PROJECTION_INCOMPLETE`; it is never guessed, coerced or dropped. Changing the
registry is a named migration with its own version, never a silent re-map.

A projected instance identity binds the build's stable publication/chain
identity, the target message definition, the schema snapshot and the registry
version. Distinct observations never collapse by economic similarity.
Re-projecting the same admitted authority under the same snapshot and registry
is a no-op: `G3-PROJECTION-IDEMPOTENT`.

### B2 Structural validation and census

Every emitted instance is validated at the schema level: syntax, the logical
model (mandatory elements, cardinality, datatypes) and declared code sets, all
against the pinned snapshot. The gate emits a census of instances emitted,
schema-valid, schema-invalid, and incomplete/unmapped, with concrete reasons.
Invalid instances are retained as explicit diagnostics; they are never silently
dropped, repaired or coerced, and a parse failure remains a visible census entry.

A schema-valid instance carries the mandatory label `STRUCTURAL_COMPATIBILITY_ONLY`.
It is not a regulatory report, not a conformance certification, not an
authorisation, and not evidence about the official tape.

<a id="G3-C"></a>
## §4 G3-C — Round-trip and loss accounting

### C1 Round-trip comparison

Each emitted instance is parsed back through the same pinned snapshot into an
ISO 20022 model view and compared field-by-field against the projection source.
Every field is classified exactly once:

```
CARRIED      — value and meaning preserved through the round trip
NOT_MODELLED — the source field has no element in the message definition
LOSSY        — represented with stated reduced precision or coverage
```

`NOT_MODELLED` and `LOSSY` are recorded outcomes, not failures and not silent
drops. `LOSSLESS` is claimed for a field only where the round trip proves exact
carry; no blanket lossless claim is made for a message or a projection.

The comparison basis is the admitted tape semantics, never raw provider bytes,
which stay local. Repository evidence holds counts, per-class field tallies and
canonical digests only: prices, quantities and raw records are hashed as
identity and never emitted, following G1 §5 and G1-D.

Round-trip verdicts are deterministic: two clean replays of the same projection
under the same admitted authority produce identical class tallies and
byte-identical comparison capsules, excluding nondeterministic packaging
provenance.

<a id="G3-D"></a>
## §5 G3-D — Official bonds CTP benchmark-readiness contract

### D1 Declared interface, not consumption

D1 declares the interface by which the future official EU bonds tape would be
admitted as a benchmark source in a later gate: the identity and provenance a
CTP-provided message set must carry, how it would be timed and pinned under A1
semantics, how it would be compared against our observed tape, and the access
and reuse conditions that must be satisfied first. It is a declared contract,
not a test of a live service, and it does not assume the bonds CTP being live.

Explicit non-actions: G3 performs no live CTP acquisition, assumes no endpoint,
claims no content of the CTP, and neither merges CTP data into the tape nor into
the G1-D divergence ledger. Until access and reuse conditions are verified
(G3-L), the CTP status is `NOT_CONSUMED` and it appears nowhere as evidence.

Any future comparison inherits the G0-E / G1 §5 mandatory limits verbatim:
`NO_COVERAGE_CLAIM`, `NO_MARKET_SHARE_INFERENCE`,
`NO_ABSENCE_OF_TRADING_INFERENCE`, no low-n generalization. Absence remains
source-scoped (`NOT_OBSERVED_IN_<source>_CAPTURE`) and never means "did not
trade".

<a id="G3-L"></a>
## §6 G3-L — Legal classification of schema and CTP artifacts

Snapshot the ISO 20022 message-definition terms and the CTP access/reuse
conditions, and classify the legal status of each artifact class under
PASS | FAIL | UNRESOLVED, extending the G0-L discipline without changing any
G0-L status. UNRESOLVED is an acceptable recorded outcome.

| Class | Question |
| --- | --- |
| `SCHEMA_ARTIFACT_VENDORING` | May the pinned schema files be committed to the repository, or only referenced by digest and public location? |
| `CTP_OUTPUT_REDISTRIBUTION` | May CTP output be stored and republished? |
| `DERIVED_MESSAGE_PUBLICATION` | May ISO 20022 instances projected from provider-derived data be published? |

Fail closed: where vendoring is not PASS-verified, the repository holds only
digests, provenance and the public location, and the schema files remain under
`data/`. The classification is a snapshot with its date; it grants no rights and
does not resolve G0-L's UNRESOLVED cells.

<a id="G3-E"></a>
## §7 G3-E — Evidence and PASS evaluation

Evaluate each criterion explicitly, cite committed metadata and show PASS or
REVIEW_REQUIRED. G3 PASS requires all of:

1. G0/G1/G2 baselines remain verifiable and unchanged; the consumed G2-C1 build
   identity is unchanged.
2. A pinned, timed schema snapshot with input/output separation and exact
   artifact digests; every declared message definition and referenced code set
   is pinned, and draft artifacts are labelled `DRAFT_SCHEMA_BASIS`.
3. The projection is a deterministic pure function of admitted authority,
   snapshot and mapping registry; `G3-PROJECTION-IDEMPOTENT` is demonstrated.
4. Every internal value crossing a code boundary has an explicit mapping or an
   explicit `G3_UNMAPPED_<field>` reason; unknown-code and missing-mandatory
   counterexamples fail closed in deterministic offline fixtures.
5. Round-trip accounting classifies every field as CARRIED / NOT_MODELLED /
   LOSSY with stated reasons; no lossless claim is made without proof.
6. The structural-validation census is complete and no instance, capture or
   field is silently dropped or coerced; every valid instance carries
   `STRUCTURAL_COMPATIBILITY_ONLY`.
7. The benchmark contract declares its interface without consuming the CTP and
   records `NOT_CONSUMED` until access/reuse conditions are verified separately.
8. Evidence is metadata-only, economic values are never emitted, CI is offline,
   and the mandatory interpretation limits are enforced by scan at emission.
9. Current G0-L classifications are preserved and the new G3-L classes are
   recorded, UNRESOLVED acceptable.
10. Two clean replays produce identical projection and round-trip digests; the
    implementation matrix and installed CLI checks are green before verification.

Unlike G2, G3 PASS does not require accrued live CTP evidence, because no bonds
CTP is authorised. Fixtures prove code semantics; a schema-valid projection is
not authorisation, not a conformance certification, and not a market-coverage
statement. Specification freeze, a smoke run or self-verification alone is not
G3 PASS.

<a id="G3-F"></a>
## §8 G3-F — Freeze and bounded contracts

Changing this specification requires a reviewed PR and a new annotated
`g3-freeze-v*` tag. Record design choices, dependencies and deviations in the
PR; do not edit G0/G1/G2 to make a new implementation pass.

After `g3-freeze-v0` exists, create A1, B1, B2, C1, D1 and L1 contracts
referencing this file's explicit anchors. Put dependency issue IDs in Allowed
scope; issues do not redraft semantics. A1 (schema authority) and L1 (legal
classification) are independent of the tape and may be `ready-for-agent` first.
B1, B2 and C1 remain `planned` until both a verified G2-C1 build and a verified
A1 snapshot exist. D1 requires A1 and recorded L1 statuses. E1 cannot verify
before B/C/D/L. Implementation may split a contract into bounded issue/PR slices
without changing this authority.
